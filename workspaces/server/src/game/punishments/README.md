# Модель наказаний

`PunishmentCase` представляет одно наказание с общей областью действия. `PunishmentBinding` связывает его с конкретной записью игрового провайдера на экземпляре Connect. Блокировка аккаунта имеет категорию `ACCOUNT` и отдельный источник в `unicore_bans`; игровые наказания имеют категорию `GAME`.

Один сервер CMS может содержать несколько адресов и процессов. `ServerInstance.id` обозначает постоянный адрес из каталога, `ConnectInstance.id` обозначает процесс с сохраняемым UUID Connect. Их связывают явно. При перестановке адресов идентификатор сохраняется.

| Модуль | Ответственность |
| --- | --- |
| `AccountRestrictionsService` | Принятие прежних блокировок аккаунта, архивирование и снятие конкретной версии блокировки |
| `PunishmentCoordinator` | Преобразование событий провайдера в общие наказания, привязка команд и распространение снятия |
| `PunishmentDeliveryService` | Состав получателей, принадлежащие группе копии, очередь и подтверждение результата |
| `PunishmentGroupsService` | Группы, основные типы и изменение состава |
| `PunishmentPolicy` | Возможность покупки и актуальная цена |
| `PunishmentPurchasesService` | Резерв, завершение, возврат и ручное решение |
| `PunishmentAccess` | Права на конкретную область и иерархия модераторов |
| `PunishmentViews` | Общая лента для сайта, кабинета и панели, счётчики и разрешённые действия |
| `PunishmentAdmin` | Выдача, снятие, перенос с просмотром, запрет продажи и сверка доставки |
| `PunishmentTasks` | Принятие прежних записей и продолжение незавершённых операций после запуска |

`punishment-capabilities.ts` описывает возможности провайдера и области без обращений к базе. API выбора области и доставка используют одну проверку операции, включая временные и бессрочные наказания.

## События и владение

Первичный снимок имеет происхождение `SNAPSHOT` и сохраняет прежнюю область. Новые `LIVE` и `POLL` события могут попасть в явно назначенную основную группу. Команда CMS связывается с записью через идентификатор команды и точный идентификатор провайдера; её копии дальше не распространяются.

Терминальное состояние записи провайдера сохраняется. Поздний ответ старой команды не меняет текущую копию. При выходе участника снимаются принадлежащие группе записи. Недоставленная команда отменяется до первого предложения серверу. Уже предложенное снятие прежней копии завершается, а после возвращения участника создаётся новая копия; такое снятие не превращается в групповой разбан.

Сетевые области провайдера сохраняются отдельно. Из них не создаются локальные групповые наказания. Для управления такой записью нужны права уровня проекта; её область показывается на сайте.

## Подтверждение и деньги

У наказания раздельны наблюдаемое состояние и желаемое состояние. Ответ команды сам по себе не подтверждает снятие: требуется терминальная запись или точное подтверждение отсутствия у провайдера. Неопределённая выдача не повторяется. Её можно связать с точной записью через проверку на игровом сервере. Ошибка этой проверки сохраняет неопределённость исходной выдачи.

Резерв уменьшает доступный `User.real` в той же транзакции, которая сохраняет покупку. Поэтому магазин и остальные потребители баланса сразу учитывают зарезервированные средства. Завершение создаёт финансовую историю без повторного уменьшения баланса. Возврат зачисляет резерв один раз.

Покупка сохраняет цену, срок и набор подтверждений. Цена проверяется по предложению, которое подтвердил покупатель. Время первого подтверждения снятия сохраняется в привязке. При истечении до полного подтверждения резерв возвращается; после суток незавершённая покупка переходит в `REVIEW`, а доставка продолжается.

Изменения модели сериализуются транзакционной блокировкой строки настроек. Операции Connect сначала блокируют свой экземпляр, затем модель наказаний. Сервисы модели не берут обратную блокировку экземпляра. Сетевые вызовы внутри этих транзакций не выполняются.

## Совместимость

Старые `/bans` управляют блокировкой аккаунта. Старый `/cabinet/game-punishments/me` сохраняет контракт записей провайдеров. Новые экраны используют `/punishments/public`, `/cabinet/punishments` и `/punishments/admin` с общей формой представления.

Публичный ответ исключает IP и CIDR и не возвращает закрытые поля пользователя. Даты передаются в UTC с явным смещением и форматируются общим помощником времени в браузере посетителя.
