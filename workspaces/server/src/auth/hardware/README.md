# Оборудование лаунчера

`HardwareService` регистрирует устройства и ключи, сопоставляет аппаратные отчёты и проверяет конкретную сессию. `HardwareAdminService` управляет самостоятельными HWID-банами и проверяет иерархию всех связанных аккаунтов. Контроллер Gravit преобразует протокол `AuthSupportHardware`; админский контроллер защищён отдельными правами. Общедоступные DTO пользователей аппаратные данные не содержат.

`HardwareDevice` хранит аппаратный отчёт. `HardwareKey` сохраняет все известные ключи устройства. `HardwareUser` представляет наблюдавшуюся связь аккаунта с устройством; одинаковое устройство у разных аккаунтов не создаёт аккаунтных блокировок. `HardwareBan` хранит отдельные версии ограничений и историю снятия. Истечение вычисляется при чтении, независимо от фонового удаления.

Сопоставление использует оценку Gravit `AuthSupportHardware.compareHardwareInfo` и расстояние Дамерау с порогом выше `1.0`. Пустые отчёты без идентификаторов отклоняются. При нескольких совпадениях действующий бан имеет приоритет, затем сравнивается оценка. Смена ключа не удаляет прежние ключи. Создание, привязка ключей и модерация сериализуются блокировкой реестра.

`HardwareSession` связан с числовым ключом `RefreshToken`; UUID токена служит идентификатором сессии Gravit. Привязка не принимает UUID пользователя из клиентского отчёта. После подтверждения устройства его нельзя сменить в той же сессии. Minecraft-токен хранится отдельно для каждой сессии, OAuth-токен содержит `launcherSession`. Это исключает использование последнего токена другого устройства того же игрока.

`HardwareJoin` связывает конкретный игровой handshake с проверенной сессией на пять минут. Удаление refresh-токена удаляет связанные записи; последующий `checkServer` не восстанавливает допуск из устаревшего поля пользователя. Восстановление OAuth, обновление токена, `joinServer` и `checkServer` читают актуальное состояние устройства.

Аппаратный режим включается явно в UnicoreProvider и защите Gravit. Для новых сессий этого режима отсутствие проверки запрещает вход в игру. Веб-сессии и остальные лаунчеры не наследуют HWID-бан. Аккаунтные ограничения остаются в `unicore_bans`, игровые наказания в модуле `game/punishments`.

Административная выдача проверяет версии всех выбранных устройств в одной транзакции. Снятие адресует точный `banId`; повтор снятия старой записи не меняет новый бан. Аудит модерации записывается после успешного завершения транзакции и не содержит серийных номеров или ключей.
